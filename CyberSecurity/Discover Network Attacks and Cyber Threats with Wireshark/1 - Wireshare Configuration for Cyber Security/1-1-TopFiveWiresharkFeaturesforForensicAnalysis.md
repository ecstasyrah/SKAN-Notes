<summary><b>Introduction to Cyber Security Analysis with Wireshark</b></summary>

## The Role of Wireshark in Cybersecurity
Understanding where Wireshark fits into the security analyst's toolkit.

### 1. A Microscopic View of Network Traffic
*   **Industry Standard:** Wireshark is the world's foremost network protocol analyzer, allowing professionals to examine traffic at a highly granular level.
*   **Primary Use Cases:** It is utilized heavily for intrusion detection, incident response, and deep forensic analysis.

### 2. The Investigation Workflow
*   **Not a First-Line Tool:** Wireshark is rarely the first tool used to blindly hunt for a cyber event. Because packet captures contain an overwhelming amount of detail, it is very easy to miss initial Indicators of Compromise (IOCs).
*   **Alert-Driven Analysis:** Typically, a high-level alert is generated by an IDS, IPS, or server log. These alerts provide the specific parameters (like timestamps, IP addresses, or ports) that guide where to start the deep-dive forensic investigation within Wireshark.

---

## Customizing Wireshark for Forensics
Default Wireshark settings are designed for general network troubleshooting, not targeted security analysis. 

### 1. Building a Security Profile
*   To effectively hunt for threats, analysts must configure a dedicated "security profile." This customizes the interface to highlight suspicious activity and streamline the forensic workflow.

### 2. Top 5 Forensic Features to Configure
Mastering the following five features is essential for transitioning from basic packet viewing to advanced incident response:
1.  **Statistics Feature:** Utilizing built-in statistical tools to quickly identify traffic anomalies and baseline deviations.
2.  **GeoIP Location Resolution:** Mapping IP addresses to physical geographic locations to spot suspicious international or out-of-policy traffic.
3.  **Custom Columns:** Modifying the packet list pane to instantly display critical security metrics without having to dig into individual packet details.
4.  **Name Resolution:** Translating raw IP and MAC addresses into human-readable hostnames to establish context around who is communicating.
5.  **Object Extraction:** Reconstructing and extracting files (such as malware payloads, scripts, or stolen documents) directly from the raw PCAP data.

<summary><b>The Statistics View</b></summary>

## The 100,000-Foot View
Analyzing traffic packet-by-packet is inefficient. The Statistics features allow analysts to back up and view the network from a high level, making it much easier to spot anomalies before diving into the details.

### 1. Protocol Hierarchy
*   **Accessing it:** 
    - Navigate to **Statistics > Protocol Hierarchy**.
*   **The Purpose:** 
    - Provides an immediate snapshot of the protocol distribution within the PCAP (e.g., how much traffic is Ethernet, IPv4, TCP vs. UDP). 
    - Helps quickly identify if unexpected or unauthorized applications are running on the network.

### 2. The Conversations View
*   **Accessing it:** 
    - Navigate to **Statistics > Conversations**.
*   **How it works:** 
    - Organizes traffic by OSI layer (Ethernet MAC addresses, IPv4 addresses, TCP/UDP ports).
*   **Spotting Red Flags (Port Scans):**
    - **Sequential IP Communication:** If a single host (e.g., `10.0.2.15`) is trying to connect to every device on a subnet sequentially (1, 2, 3, 4, 5...), this is highly unusual for an end-user device.
    - **Imbalanced Packet Counts:** Look for high traffic going from `A → B`, but zero or very few responses going from `B → A`. This indicates the host is blindly probing systems.
    - **Targeted Port Probing:** By navigating to the TCP tab and sorting by port, you can identify if a host is systematically checking common ports (e.g., 21 for FTP, 22 for SSH, 23 for Telnet, 80 for HTTP, 135/445 for RPC/SMB). Most single-packet conversations with no response signify a port scan.

### 3. Pivoting to Deep Analysis
*   **Applying Filters from Statistics:** 
    - If you spot suspicious activity in the Conversations view, you don't need to manually type a filter.
    - Simply **right-click** the suspicious conversation line, select **Apply as Filter > Selected > A <-> B**.
    - Close the Statistics window, and Wireshark will immediately display only the packets associated with that specific, suspicious conversation for deep-dive validation.

### Ports
21 - FTP
22 - SSH
80 - HTTP
443 - HTTPS
631 - IPP

## The Value of GeoIP in Forensics
Understanding the geographical origin and destination of network traffic is critical for spotting unauthorized international connections or out-of-policy data transfers.

### 1. Acquiring the GeoIP Databases
*   **The Source:** 
    - Wireshark relies on external databases to map IP addresses to physical locations. The industry standard provider is **MaxMind** (maxmind.com).
*   **Required Databases:** 
    - You need the GeoLite2 (free version) databases covering **ASN (Autonomous System Number)**, **City**, and **Country**.
*   **Preparation:** 
    - Ensure these databases are downloaded and unzipped into a dedicated, permanent folder on your system.

> ⚠️ **Safety Disclaimer: Working with Malware PCAPs**
> This lab utilizes trace files sourced from *malware-traffic-analysis.net*. While opening and analyzing these PCAPs within Wireshark is completely safe, **do not** extract the files and execute them (especially on a Windows machine), as they contain live, active malware.

---

## Configuring Wireshark for GeoIP
Pointing Wireshark to your downloaded MaxMind databases to enable location resolution.

### 1. The Setup Process
*   **Accessing Preferences:** 
    - On Windows/Linux: Navigate to **Edit > Preferences**.
    - On macOS: Navigate to **Wireshark > Preferences**.
*   **Linking the Databases:** 
    - Select **Name Resolution** from the left sidebar.
    - Scroll down to the **MaxMind database directories** section.
    - Click **Edit**, add the file path to the folder containing your unzipped GeoLite2 databases, and click **OK**.
*   **Verification:** 
    - You may need to restart Wireshark. Once active, selecting a public IP packet should display Country, ASN, and Latitude/Longitude details in the packet dissection pane.

---

## Analyzing Geographic Data
Once configured, GeoIP data becomes available in both packet details and high-level statistical views.

### 1. Endpoint Statistics
*   **Viewing the Data:** 
    - Navigate to **Statistics > Endpoints** and select the **IPv4** tab.
*   **What You Will See:** 
    - The table will now populate columns for Country, City, AS Number, and AS Organization for all external IP addresses.
*   **Private Address Behavior:** 
    - Internal/Private IPs (e.g., `10.x.x.x`, `192.168.x.x`, `172.16.x.x`) will display dashes (`-`), as they are non-routable and do not possess a public geographical location.

### 2. Visualizing Traffic on a Map
*   **The Map Tool:** 
    - From the IPv4 Endpoints window, click the **Map** button at the bottom and select **Open in browser**.
*   **The Result:** 
    - Wireshark will plot all the known GeoIP coordinates onto an interactive web map, allowing you to instantly visualize where in the world your network is communicating.

<summary><b>Lab 4 - Configuring Custom Columns</b></summary>

## Enhancing the Packet List Pane
Adding custom columns brings critical data to the forefront, allowing analysts to spot anomalies without digging into individual packet details.

### 1. Adding Source and Destination Ports
*   **The Initial Setup:** 
    - Select a TCP packet, expand the Transmission Control Protocol (TCP) header in the details pane.
    - Right-click **Source Port** and select **Apply as Column**. Repeat this process for **Destination Port**.
    - Drag the new columns next to the Source and Destination IP columns for readability.
*   **Supporting UDP Traffic:** 
    - By default, this setup only shows TCP ports (leaving UDP traffic like DNS blank).
    - Right-click the new Source Port column header and select **Edit Column**.
    - Change the *Fields* entry to: `tcp.srcport or udp.srcport`.
    - Repeat for the Destination Port column: `tcp.dstport or udp.dstport`.
    - *Result:* The columns will now display port numbers for both TCP and UDP traffic.

---

## Spotting Suspicious Domains with the HTTP Host Column
While much traffic is encrypted today, malware and compromised systems still frequently communicate over unencrypted HTTP.

### 1. Creating the HTTP Host Column
*   **Filtering for HTTP:** 
    - Type `http` into the display filter to isolate web traffic.
*   **Adding the Column:** 
    - Select an HTTP HTTP packet, expand the Hypertext Transfer Protocol header.
    - Right-click the **Host** field and select **Apply as Column**.
*   **Analysis Application:** 
    - Click the new Host column header to sort the traffic alphabetically.
    - This allows analysts to quickly scan the list of servers the network is communicating with, making it easier to spot unusual or suspicious domains (e.g., obscure advertising networks, random character strings, or known malicious hosts).

---

## Managing Your Workspace
As an investigation evolves, you will need to add, remove, and modify columns frequently.

### 1. Hiding and Restoring Columns
*   **Temporary Removal:** 
    - If a column is no longer needed (e.g., the Host column when analyzing non-HTTP traffic), right-click any column header and uncheck it from the list to hide it.
*   **Restoring:** 
    - To bring it back, right-click the headers again and re-check the box. This keeps the profile clean without permanently deleting your custom configurations.

## Lab 5 – Configuring Name Resolution
- Configure Wireshark to display readable names for MAC addresses, port numbers, IP addresses, and IPv6 addresses.

### Step 1: Open Name Resolution Settings
- Access the settings used to configure name resolution.

1. Open **Wireshark**.
2. Select **Edit**.
3. Select **Preferences**.
4. Choose **Name Resolution**.

### Step 2: Resolve MAC Addresses
- This displays the device manufacturer instead of only the complete MAC address.

1. Enable **Resolve MAC addresses**.
2. Check the source and destination columns for resolved manufacturer names.

#### How It Works
- Wireshark compares the MAC address prefix with a list of registered manufacturers. For example, it may identify a device as an Apple product.

### Step 3: Resolve Transport Names
- This replaces recognized TCP and UDP port numbers with their service names.

1. Enable **Resolve transport names**.
2. Check the **Info**, **Source Port**, and **Destination Port** columns.

#### Examples
- UDP port `53` may appear as `DNS`.
- TCP port `443` may appear as `HTTPS`.
- High-numbered or unknown ports may remain displayed as numbers.

### Step 4: Resolve Network Addresses
- This replaces IPv4 and IPv6 addresses with available hostnames.

1. Enable **Resolve network (IP) addresses**.
2. Select the preferred name-resolution methods.

#### Default Resolution Sources
- If no additional options are enabled, Wireshark uses its hosts file and the name-resolution blocks stored in the capture file.

### Step 5: Use Captured DNS Data
- This allows Wireshark to resolve addresses using DNS requests and responses found inside the PCAP file.

1. Enable the option to use captured DNS packet data.
2. Wireshark will match requested domains with the IP addresses returned in DNS responses.

#### Example
- If the capture contains a DNS request and response for `google.com`, Wireshark can associate the returned IP address with that hostname.

#### Limitation
- Wireshark cannot use this method when the related DNS request or response is missing from the capture.

### Step 6: Use an External DNS Resolver
- This allows Wireshark to actively resolve captured IP addresses using a DNS server.

1. Enable the external network name resolver.
2. Use the computer’s default DNS server or configure a specific DNS server.
3. Review the captured addresses after resolution begins.

#### Traffic Warning
- Active resolution can generate many DNS requests, especially when working with large capture files.

### Step 7: Limit Concurrent DNS Requests
- This controls how aggressively Wireshark sends DNS queries.

1. Locate **Maximum concurrent requests**.
2. Enter the maximum number of outstanding DNS requests.
3. Use a lower value if you want Wireshark to generate less DNS traffic.

#### Example
- A value of `500` allows up to 500 outstanding DNS requests at one time.

### Step 8: Apply the Settings
- Save the configuration and display the available resolved names.

1. Click **OK**.
2. Check whether IP addresses, port numbers, and MAC addresses now have readable names.

### Step 9: Assign a Name Manually
- Manual names are useful for devices that do not have DNS names or cannot be identified from the PCAP.

1. Right-click the IP address.
2. Select **Edit Resolved Name**.
3. Enter a recognizable name, such as `Client`.
4. Click **OK**.

### Step 10: Remove a Manual Name
- Remove an assigned name to display the original IP address again.

1. Right-click the renamed address.
2. Select **Edit Resolved Name**.
3. Delete the assigned name.
4. Click **OK**.

### Key Takeaway
- Name resolution makes forensic analysis easier by replacing technical addresses and ports with readable names. Use active DNS resolution carefully because it generates additional network traffic.

## Lab 6 – Exporting HTTP Objects and Files
- Export files and other objects contained in HTTP traffic from a PCAP using Wireshark.

### Required Capture File
- Open the **Lab 6 Part 1 – Exporting Objects PCAP** file.

### HTTP Traffic
- Port `80` commonly uses HTTP, which normally transfers data without encryption.

#### Important Correction
- Port `80` is associated with **HTTP**, not HTTPS. HTTPS commonly uses port `443` and encrypts its traffic.

#### Encrypted Traffic
- Files carried through encrypted traffic are difficult to extract unless the traffic is decrypted first.

### Purpose of Exporting Objects
- Exporting allows investigators to examine files delivered to a system and determine whether they are safe or malicious.

#### Malware Analysis
- Suspicious files can be analyzed in an isolated environment or submitted to a service such as **VirusTotal**.

### Supported Application Protocols
- Wireshark can natively export objects from several protocols, including HTTP, SMB, TFTP, mail, and DICOM.

### Step 1: Open the PCAP
- Load the packet capture containing the HTTP objects.

1. Open **Wireshark**.
2. Open the **Lab 6 Part 1 – Exporting Objects PCAP** file.
3. Locate the traffic using port `80`.

### Step 2: Open the Export Objects Window
- Access Wireshark’s built-in object-exporting feature.

1. Select **File** from the menu.
2. Select **Export Objects**.
3. Choose **HTTP**.

### Step 3: Review the Available Objects
- Examine the HTTP objects found inside the PCAP.

#### Displayed Information
- **Hostname** shows where the file originated.
- **Content Type** identifies the type of file.
- **Size** shows the file’s total size.
- **Filename** displays the object’s name.

### Step 4: Select an HTTP Object
- Choose the file that you want to extract from the packet capture.

1. Locate the object from `ubuntugeek.com`.
2. Select the PNG image named `ubuntu1`.
3. Confirm that its size is approximately `10 KB`.

### Step 5: Save the Object
- Export the selected file to a folder on the computer.

1. Select the desired object.
2. Click **Save**.
3. Choose a destination folder.
4. Confirm the filename and extension.
5. Complete the save operation.

### Step 6: Verify the Exported File
- Confirm that the selected object was successfully extracted.

1. Open the destination folder.
2. Locate the exported image.
3. Open it only if the capture and file are confirmed to be safe.
4. Verify that the image displays correctly.

### Lab Safety
- The objects in this specific lab PCAP have been filtered and are considered safe to export.

### General Security Warning
- Objects extracted from unknown or suspicious traffic may contain malware.

#### Safety Precautions
- Do not directly open unknown executable, binary, or document files.
- Analyze suspicious files in an isolated virtual machine or sandbox.
- Remember that Windows, Linux, and macOS can all be affected by malicious files.
- Do not upload confidential files to public malware-analysis services.

### Key Takeaway
- Use **File → Export Objects → HTTP** to review and save files transferred through unencrypted HTTP traffic. Always handle objects from suspicious captures carefully.
